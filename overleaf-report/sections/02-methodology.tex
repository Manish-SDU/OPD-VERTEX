\section{Methodology}

\subsection{Teamwork and Collaboration}

Tasks were distributed in pairs throughout most of the project, which supported collaboration and peer review. The workflow was organized in Trello across five sprints, allowing the team to track and manage tasks as the project evolved.

In Sprint 1, the team focused on planning the project structure by preparing the project proposal, creating initial diagrams, and designing the database. In Sprint 2, the team set up the application environment, designed the first draft of the user interface, configured both SQL and NoSQL databases, and implemented authentication features for patients, doctors, and administrators.

In Sprint 3, the team implemented audio capture and speech-to-text transcription, fixed and improved the database, and prepared the project presentation for the midterm seminar. In Sprint 4, the team implemented document versioning and editing, added email sending functionality, integrated LLM capabilities for transcription, suggestions, and reports, and completed the user interface implementation. In Sprint 5, the team fixed the last bugs, updated the diagrams, created the final seminar presentation, and finished the report.

GitHub was used to share and manage the code, allowing the team to collaborate efficiently while keeping all contributions organized in one place. The team met around twice per week to review progress, coordinate tasks, and resolve blockers. WhatsApp was used mainly for daily updates, while Discord was used for sharing files, data, and other project resources.

\subsection{Application of Course Knowledge}

The application was developed using a component-based architecture, following concepts from the Component-Based Systems course. This approach made it easier for team members to work in parallel on different parts of the system without interfering with each other's progress. By separating the application into independent components, development became more organized, scalable, and easier to maintain.

Testing was carried out throughout the development process, applying principles from the Designing Software Systems with Embedded Elements course. Instead of leaving testing only for the final stages, features were regularly checked and improved as they were implemented, helping the team identify issues earlier and maintain a more stable system overall.

An LLM was integrated into the application to support features such as Suggestive Mode. This part of the project combined ideas from the Artificial Intelligence course and the Algorithms and Data Structures course, especially in terms of data processing, optimization, and AI-driven functionality.

The team also applied knowledge gained during the previous semester by using Docker for containerization, which simplified deployment and ensured a more consistent development environment across all machines. Concepts from the Data Management course were used to design the database architecture, which was split into MySQL for structured relational data and MongoDB for document-oriented storage. This separation allowed each database to be used where it was most appropriate, improving efficiency and data organization.
